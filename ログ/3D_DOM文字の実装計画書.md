# 3D_DOM文字の実装計画書

## なにをしたいか

3Dの中に置いた文字も、本物のHTMLとして出したい。
そうすれば3Dの作品でも、文字が検索に出て、選んでコピーできて、読み上げも効く。

いまは2Dの文字だけがHTMLになる。3Dの空間に置いた文字はGodotの絵のままなので、
検索にも選択にも出てこない。

これは後の段階でやる。この文書は、やるときに何をどうするかを決めておくもの。

## できる見込みがあるわけ

CSSには `matrix3d` と `perspective` がある。これを使うと、HTMLの要素を
3Dの空間に置いたように見せられる。奥のものは小さく、手前のものは大きくなる。

手元のChromiumで実際に確かめた。`perspective:600px` の中へ、奥行きだけ違う
同じ文字を三つ置いた結果。

| 奥行き | 文字の幅 | 実測の倍率 | 計算した倍率 |
|---|---|---|---|
| z = -200 (奥) | 30.7px | 0.751 | 0.750 |
| z = 0 | 40.9px | 1.000 | 1.000 |
| z = +100 (手前) | 49.1px | 1.200 | 1.200 |

計算式は `倍率 = perspective / (perspective - z)`。実測と計算が小数三桁まで合った。
文字は選択もコピーもできたままだった。

つまり、この道は通る。

## 全体の形

いまの2Dの仕組みと同じ組み立てにする。Godot側が位置を決め、JavaScript側がDOMへ移す。
違うのは、渡す行列が6個の値から16個の値になるところ。

```
Godot(C++)                          Browser(JS)
─────────────────────────────────────────────────────
Label3Dなどの文字を見つける
  │
  ├ 世界での位置と向きを取る
  ├ Cameraの見え方と合わせる
  │
  └ 16個の値として渡す ─────────> matrix3d(...) をstyleへ書く
                                    親には perspective を一度だけ書く
```

## 三つの決めごと

### perspectiveの値をCameraから作る

Godotの `Camera3D` は視野角(fov)で見え方を決める。CSSは距離(px)で決める。
画面の高さから、同じ見え方になる距離を出す。

```
perspective(px) = (画面の高さ / 2) / tan(fovの半分)
```

これはthree.jsのCSS3DRendererが使っているのと同じ考えかた。
親要素へ一度だけ書けばよく、要素ごとには要らない。

### 行列の並びと、上下の向き

CSSの `matrix3d` は16個の値を縦に並べる順(列優先)で受け取る。
Godotの `Transform3D` から取り出すとき、この並びへ直す。

もう一つ、上下が逆になる。3Dの世界はYが上へ増えるが、CSSはYが下へ増える。
だからYに関わるところの符号を反転させる。ここを間違えると、文字が上下さかさまに出る。

### 文字の向きの二種類

| 種類 | 見えかた | 使いどころ |
|---|---|---|
| 世界に貼りつく | 3Dの面と一緒に傾く。回すと斜めに見える | 看板、床の文字 |
| いつも正面 | 向きは変えず、奥行きの大小だけ変わる | 名前ラベル、吹き出し |

「いつも正面」のほうが先。行列の回転部分を単位行列へ置き換える形になり、
文字も読みやすいまま。「世界に貼りつく」は回転が入ると字が潰れて読みにくくなるので後。

## できないこと

ここは正直に書いておく。あとで期待外れにならないように。

**そのままでは、3Dのものと文字が前後で混ざらない。**
DOMはまるごと一枚の層として扱われる。canvasの中の奥行きの情報は、
画面へ出す時点で捨てられている。だから素直に重ねると、
文字はいつも3Dの絵の手前か、いつも後ろかのどちらかになる。

ただし、抜け道はある。順番をひっくり返す方法。

1. 文字の層をcanvasの**下**へ置く
2. canvasの背景を透明にする
3. 文字を隠したいところへ、色を書かず奥行きだけ書く板を3D側へ置く

こうすると、手前に3Dのものがあるところはcanvasが不透明のままで文字を隠し、
何も無いところはcanvasが透明なので下の文字が透けて見える。
隠すかどうかの判定を、3Dの奥行きの仕組みへ任せる形になる。

手元のChromiumで実際に確かめた。canvasの左半分を不透明、右半分を透明にして、
下に文字を置いた結果。文字は境目のちょうどそこで切れた。
文字の途中で切れているので、これは要素まるごとの出し入れではなく、
点の細かさで隠れていることになる。

代わりに失うものもある。canvasへ後から効果(光のにじみなど)をかけると、
透明にしたところが塗り潰されて元に戻ってしまう。

だから段取りとしては、まず素直に手前へ出す形で作る。
前後で混ぜたくなったら、この抜け道へ進む。

**カメラの後ろへ回った文字。**
`perspective - z` が0や負になると、CSSの見た目が壊れる。
カメラより後ろにある文字は、DOMへ渡す前にGodot側で落とす。

**祖先に `overflow:hidden` があると、3Dが平たく潰れる。**
CSSは、途中の要素に `overflow` が `visible` 以外、`opacity` が1未満、`filter`、
`mix-blend-mode` などがあると、そこで3Dの積み重ねを打ち切る。

手元のChromiumで測った。奥へ200px下げた同じ文字の幅。

| 途中の要素 | 文字の幅 | 奥行きが効いたか |
|---|---|---|
| `overflow:visible` | 948px | 効いた |
| `overflow:hidden` | 1264px | 潰れた |
| `overflow:clip` | 1264px | 潰れた |

`overflow:clip` なら大丈夫という話を見かけるが、手元では `hidden` と同じく潰れた。
どちらも使えない。

いまの文字のrootは `overflow:hidden` を持っている。
3Dをやるときは、ここをどうするかを最初に決める必要がある。
はみ出しを抑える役目があるので、単に外すのではなく、
3Dの文字は別のrootへ分ける形になりそう。

**文字の見た目が少し細くなる。**
3Dの変形がかかった文字は、ブラウザが横方向の細かい色づけをやめる。
読めなくなるほどではないが、同じ文字を平たく置いたときより薄く見える。
これは切り替えられない。

**行列の細かさは6桁で切られる。**
手元のChromiumで確かめた。`0.12345678901234567` を渡しても、
返ってくるのは `0.123457` になる。だからGodot側で細かい値を作り込んでも、
その細かさは残らない。位置がじわじわずれる作りにしないこと。

奥行きが実質ゼロの文字は、ブラウザが `matrix3d` を平たい `matrix` へ
勝手に畳む。これは見た目の結果が同じなので問題にはならないが、
書いた値がそのまま返ってくると思って検査を書くと食い違う。

## 段取り

一気にやらず、確かめながら進む。

1. **正面向きの文字だけ。** `Label3D` を一つ、奥行きだけ変えて出す。
   実測した倍率の式のとおりに大きさが変わることを確かめる
2. **カメラが動いても追う。** カメラを回して、文字が正しい場所に居続けることを確かめる
3. **カメラの後ろを落とす。** 後ろへ回った文字が消えることを確かめる
4. **世界に貼りつく向き。** 回転を入れた行列を通す
5. **前後で混ぜる。** 層の順をひっくり返し、奥行きだけ書く板で文字を隠す

各段で、文字が選択とコピーの対象のままであることも一緒に見る。
そこが崩れたら、この仕組みをやる意味がなくなるから。

## 確かめかた

`tests/scene_3d.cjs` と同じ形で、Playwrightから実際のブラウザで見る。

- 奥行きの違う文字の幅を測り、`perspective / (perspective - z)` と合うか
- カメラを回したあと、文字の位置がGodotの計算と合うか
- 文字を選んでコピーできるか
- カメラの後ろの文字が消えているか
- 祖先に `overflow:hidden` が混ざっていないか

数が増えたときの重さは [カリングアルゴリズム.md](カリングアルゴリズム.md) のほうで扱う。
