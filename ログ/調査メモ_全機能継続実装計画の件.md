# 調査メモ 全機能継続実装計画の件

Godot 4.7.1限定Web出力の残機能を、途中停止せず完了判定まで進めるための公式仕様確認。
調査日: 2026-08-14

## 結論

- Web templateはEmscripten 4.0.0以上、SCons、固定sourceから再現build可能
- `threads=no`、`javascript_eval=no`は本家Web buildの正式な選択肢
- PopupMenuは`Popup`、`Window`を継承。Control通知だけのDOM同期では不足
- PopupMenuは不可視が既定。Windowのpopup操作、focus、外側操作、検索を同期対象化
- CSS transformは局所座標系、stacking context、子の包含blockを生成
- 親子DOMとGodot親子を一致させ、`transform-origin:0 0`と親相対行列を使う設計が必要
- Canvas 2D画像は`ImageData`、`putImageData()`、`drawImage()`でCPU画素から描画可能
- 標準Godot WebがWebGL 2.0を前提にするため、gdwebは本家Web設定だけでなく独自Canvas 2D経路の不在検査が必要

## 計画への反映

1. ControlとWindowを同じstable handle台帳へ収録
2. Popup、Dialog、MenuをWindow通知からdirty同期
3. DOM変換はGodot親相対行列だけを使用
4. Canvas命令、DOM、入力、Windowを一回のBrowser起動で比較
5. build引数、Emscripten、template hashを固定
6. GPU API不在をsource、Wasm import、生成JavaScript、実行時contextの四層で検査
