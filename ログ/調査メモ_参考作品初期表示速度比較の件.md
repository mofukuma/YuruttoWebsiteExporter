# 参考作品初期表示速度比較

## 条件

同一のGodot作品、GDScript、画像、1440×960 pxをgdwebとGodot 4.7.1の通常Webへ書き出し。Chromium 1194、localhost、同一HTTPヘッダーでcoldとwarmを各7回測定。中央値とnearest-rank p95を使用。

## cold

| 指標 | gdweb median / p95 | 通常Web median / p95 | median削減 |
|---|---:|---:|---:|
| HTML FCP | 60 / 64 ms | 48 / 64 ms | -25.00% |
| 初回Canvas表示 | 357.1 / 513.9 ms | 746.5 / 826.0 ms | 52.16% |
| 操作可能 | 408.2 / 561.9 ms | 752.9 / 830.7 ms | 45.78% |
| 転送量 | 22,770,677 B | 42,847,517 B | 46.86% |

## warm

| 指標 | gdweb median / p95 | 通常Web median / p95 | median削減 |
|---|---:|---:|---:|
| HTML FCP | 52 / 56 ms | 52 / 64 ms | 0% |
| 初回Canvas表示 | 345.4 / 353.9 ms | 724.5 / 884.6 ms | 52.33% |
| 操作可能 | 396.5 / 433.6 ms | 747.7 / 889.8 ms | 46.97% |
| 転送量 | 17,400,406 B | 39,513,391 B | 55.96% |

## 判定

Wasm応答を700 ms遅らせた試験で、作品見出しは70 msで表示。Godotの進捗画面は表示0件。完成画面相当のHTMLをWasmより先に描画する。

coldのHTML FCPは12 ms遅いが、初回Canvasは389.4 ms、操作可能は344.7 ms速い。warmのHTML FCPは同値、初回Canvasは379.1 ms、操作可能は351.2 ms速い。

証拠は`tmp/daito-site/performance.json`。実行は`node tests/daito_performance_compare.cjs`。
