# 実装計画_書き出しレベル分割

書き出しを三段へ分け、作品の性質に合ったテンプレートだけを配る。

## 三段の位置づけ

| Level | Canvas | 3D | 想定 |
| --- | --- | --- | --- |
| DOM only | 使わない | 無し | 一般的なWebサイト。全要素をDOMで再現 |
| 2D | 使う | 無し | 2Dゲーム。文字はDOM、描画はCanvas |
| 3D | 使う | 有り | 3Dゲーム。文字はDOM、描画はCanvas |

2Dと3DはCanvasを持つため、DOM化して再現しきれない表現はCanvasへ残す。
`RichTextLabel`のBBCodeと`CodeEdit`の色分けはCanvasへ置き、落とさない。
これらをHTMLとして出したい場合はDOM onlyを選ぶ、という使い分けにする。

## 設定と成果物

Export設定へ`yweb/level`を足し、`DOM only`、`2D`、`3D`から選ぶ。
テンプレートはlevelごとに別のwasmを持ち、addonは選ばれた一つだけを成果物へ入れる。
`templates/`へ`yweb-dom.zip`、`yweb-2d.zip`、`yweb-3d.zip`を置き、`manifest.json`は三つ分の由来とhashを並べる。
配布zipは三つを内包するため大きくなるが、書き出した作品には一つしか入らない。

## build option

入口は`build/build_distribution.sh`の一つに保ち、levelはoptionで選ぶ。
共通のSCons optionは`build/template.options`、levelごとの差だけを`build/levels.options`が一行ずつ持つ。
差は描画と物理の有無に絞り、同じsource treeから三度buildして三つのzipへ詰める。

- DOM only: `opengl3=no`で描画driverを積まない
- 2D: `opengl3=yes disable_3d=yes`
- 3D: `opengl3=yes disable_3d=no disable_physics_3d=no`

DOM onlyでWeb DisplayServerがcanvas無しに起動できない場合は、寸法1のcanvasを置いて描画命令を止める。
Godotのlayout計算だけを動かし、画面はDOMが持つという境界は変えない。

## DOM onlyの作り

階層は作らず、全Controlを`position: absolute`の要素として並べる。
Godotが確定した矩形を毎frame受け取り、`left`、`top`、`width`、`height`へそのまま書く。
既存の文字同期と同じ経路を使い、対象をLabelとButtonから全Controlへ広げる。

- 位置と寸法: `get_global_rect()`をCanvas座標のまま渡す。Browser側でlayoutを解き直さない
- 見た目: Themeの`StyleBox`を読み、CSSへ写す。`StyleBoxFlat`は背景色、border、角丸、影が素直に対応する
- 画像: `TextureRect`と`Sprite2D`はtextureをPNGへ書き出して`img`で出す
- 重なり: `z-index`をSceneTreeの並び順から与える
- 描画命令: `_draw()`の直接描画はDOM onlyでは再現対象外。使う作品は2Dを選ぶ

## 検査

Godotとブラウザの画面を同じ寸法で撮り、`compare -metric MAE`で正規化MAE 0.01未満を目標とする。
比較用sceneはWeb fontを明示し、両者のfontを揃える。差が出た要素を特定できるよう、要素ごとの矩形も併せて記録する。

## 進め方

1. levelの設定項目と、選ばれたtemplateだけを使う仕組みを入れる。既存の2Dを`2D`として通す
2. 三本のbuild optionを用意し、三つのzipを作るbuildへ変える
3. DOM onlyのDisplayServerがcanvas無しで起動するか実機で確かめる。ここが最大の未確認点
4. Control全種のDOM同期とTheme→CSS変換を実装する
5. MAE比較testを作り、差の大きい要素から詰める
6. 3Dを`disable_3d=no`で通し、文字DOMが3D作品でも出ることを確かめる
